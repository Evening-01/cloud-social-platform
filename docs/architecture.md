# 架构设计文档 — Cloud Social Platform

> 版本：v1.0 ｜ 状态：步骤 1 交付物 ｜ 关联：`WORKFLOW.md` 步骤 1

## 1. 架构决策

### 1.1 架构风格：模块化单体（Modular Monolith）

**决策**：采用「模块化单体」架构，按业务域划分模块，单一部署单元，预留微服务演进空间。

**理由**（课程场景）：
- 部署简单：单个 Spring Boot JAR，2 核 2G 服务器可承载
- 开发效率高：无分布式复杂度（服务发现、分布式事务、链路追踪）
- 团队规模小：单体更利于快速迭代与演示
- 演进空间：模块间通过接口隔离，未来可按需拆分（点赞模块 → 独立微服务）

**演进路径**：`模块化单体 → 点赞服务独立（高并发瓶颈） → 内容服务独立 → 全微服务`

### 1.2 技术选型

| 层 | 技术 | 选型理由 |
|---|---|---|
| 后端 | Kotlin 1.9 + Spring Boot 3.x | 课程要求 + 现代 JVM 生态 |
| ORM | Spring Data JPA (Hibernate) | 标准 ORM，DDD 友好 |
| 数据库 | MySQL 8.0 | 关系型主存储 |
| 缓存 | Redis 6.0 | 点赞实时计数、限流 |
| 认证 | JWT (jjwt) | 无状态认证 |
| 视频处理 | FFmpeg | 服务端转码 + 缩略图 |
| 对象存储 | 阿里云 OSS | 图片/视频 CDN 加速 |
| 前端 | React 18 + Vite + TypeScript | 现代工程化 |
| UI | shadcn/ui + Tailwind CSS | 125k★ 组件库，深度定制 |
| 部署 | Nginx + systemd | 反代 + 进程守护 |

## 3. 后端模块划分（DDD 分层）

```
backend/src/main/kotlin/com/cloudsocial/
├── config/          # Security、Redis、CORS、OpenAPI、WebMvc
├── common/          # 统一响应 ApiResponse、错误码、工具类
├── user/            # 用户域：注册/登录/JWT/个人信息
├── content/         # 内容域：图文视频上传/Feed流/详情
├── like/            # 点赞域：点赞/取消/统计/排行榜
├── share/           # 分享域：短链生成/落地页/追踪
└── exception/       # 全局异常处理器 + 业务异常
```

**依赖规则**：上层依赖下层，域之间通过 Service 接口通信，禁止跨域直接访问 Repository。

## 4. 核心业务流程

### 4.1 内容上传流程（分片 + 转码）

```
客户端 → 分片上传(每片5MB, 断点续传) → 服务端合并
     → 文件类型嗅探校验（魔数）→ 大小校验（图≤10MB, 视频≤500MB）
     → 视频: FFmpeg 转码(H.264) + 抽取缩略图
     → 上传 OSS → 记录 media_file 表 → 返回内容 ID
```

### 4.2 点赞流程（缓存 + 持久化 + 防刷）

```
点赞请求 → Redis 滑动窗口限流（10次/分钟/内容）
        → Redis INCR like_count:{contentId}（实时计数）
        → MySQL 写 like_record（唯一索引防重复）
        → 定时任务：Redis 计数落库（对齐最终一致性）
```

### 4.3 分享链接流程

```
生成分享 → Base62 生成 8 位短码 → Redis + MySQL 双写映射
访问短链 → 查询映射 → 落地页渲染 + 访问日志（UTM 解析）
安全   → 签名校验 + 单 IP 限流（100次/小时）
```

## 5. 部署架构（阿里云）

```
公网 IP 121.40.108.157（2C2G + 2G swap）
├── Nginx (80/443)     — 静态资源 + API 反代 + HTTPS
├── Spring Boot (9090) — 社交平台后端（JVM -Xmx512m）
├── Spring Boot (8080) — 图书项目（已存在，互不影响）
├── MySQL 8.0 (3306)   — social_platform + library 两库
├── Redis 6.0 (6379)   — 点赞缓存 + 限流
└── OSS                — 图片/视频对象存储
```

**端口约定**：9090（社交平台）、8080（图书项目）、3306（MySQL）、6379（Redis）。

## 6. 非功能需求

| 维度 | 方案 |
|---|---|
| 安全 | JWT + 接口限流 + XSS/CSRF 防护 + 文件上传嗅探 + HTTPS |
| 性能 | Redis 缓存 + 图片懒加载 + 前端代码分割 + Gzip |
| 可用性 | 健康检查端点(Actuator) + 优雅停机 + swap 兜底 |
| 可观测 | Logback 日志 + 简单监控（课程场景够用） |
| 备份 | MySQL 每日全量备份 + binlog 增量 |

## 7. 风险与约束

| 风险 | 应对 |
|---|---|
| 2G 内存紧张 | JVM 限 512m、MySQL 调优(156MB)、Redis 限 128m、2G swap |
| 视频转码内存峰值 | 转码任务串行 + 低并发（课程场景） |
| 与图书项目共存 | 端口隔离(9090 vs 8080)、数据库隔离(social_platform vs library) |
| GitHub 访问慢 | 已配置 git 代理（127.0.0.1:7897） |
